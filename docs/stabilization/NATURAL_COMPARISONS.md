# Natural-image Ultra HDR comparison protocol

This additive test uses five reusable-license, nonpersonal photographic fixtures. Inputs are ordinary SDR-origin rasters; none is described as a verified HDR capture. The SDR rendition, explicit Ultra HDR eligibility and reconstruction error are measured separately. The baseline capture retains option A and clipped Social. The final capture uses the chosen production C shoulder in both Social and Ultra HDR, with an exact frozen A counterfactual on the same new-shader stress render. This artifact protocol does not establish a physical-panel visual approval.

Fixtures and exact byte identities are in [sources.json](../../core/export-pipeline/src/androidTest/assets/natural-comparisons/sources.json). The input files are retained unchanged in that directory. Sources were checked on 2026-10-26.

The opt-in `NaturalComparisonArtifactsDeviceTest` decodes to software linear extended-sRGB F16 using the same Android decoding color space as production, verifies no source gain map, and registers the image with the production GlStoryRenderer. The full-height centered 9:16 crop is recorded per fixture. Two output settings are compared: typical AZURE contrast .5/exposure 0, and deliberately strong AZURE contrast 1/exposure +1. Remaining GradeParams values are defaults. The latter is a controlled grade stress case; applying exposure does not establish HDR source provenance. HDR Story Boost is off.

Both formats use UHD_4K (2160×3840). This is deliberate: Social at HD_1080 renders at 2× while Ultra HDR at HD_1080 renders at 1×. At UHD the production render size is identical, and there is no resampling. Both branches use production LumaSharpen defaults. In the final capture both Social and Ultra HDR then use production C base mapping; the original baseline used clipped Social. The test hashes every raw F16 render and requires the Social and Ultra request hashes to match exactly before reporting a paired set. The hash serializes all half words in row-major, RGBA order, big-endian. All actual files pass through ExportProcessor and the production JPEG/platform Ultra HDR encoders.

The baseline sets contain explicit clipped Social, current-at-that-time A production Ultra requests, decoded primary SDR bases and sidecars; stress C was a test-only direct encode. Final sets contain production C Social and C Ultra requests (`-C_requested-ultra`), decoded bases and sidecars. Final stress sets also contain a frozen pre-C A direct-platform encode (`_requested-ultra`) and base, explicitly labeled counterfactual. The frozen A object is an exact copy of the pre-C GainMapMath object apart from package, imports and object name; original source SHA256 is 2d0f85d880709556dd89bc53011ed3028dce378ba865a93409f33fc9b4caf8a1. Sidecars retain settings, inputs, render/output hashes and actual result format. A fallback remains named `requested-ultra` and explicitly reports SOCIAL_STORY_JPEG; it is never represented as an actual Ultra HDR file. Stress cases require an actual decoded gain map. PNG export removes the gain map and checks every decoded pixel round-trips exactly. Separate neutral and AZURE contrast1 probes record the pre-sharpen eligibility ratio on the same UHD crop.

SDR appearance metrics compare decoded primary-base luminance against the explicit decoded Social JPEG, grouped by Social luminance: shadows .02–.18, midtones .18–.6, highlights .6–1. They report mean luminances and the fraction of samples darkened by over 5%. These are spatial luminance bins, not semantic skin masks or a visual approval.

Numerical metrics reconstruct full gain from the actual decoded base and actual decoded gain bitmap, against the nonnegative sharpened F16 target. Sampling takes one pixel per8×8 block with x/y offsets1–4 cycling independently by block index, balancing all16 phases of a fixed4×4 evaluation cell, independent of encoded gain density. Gain interpolation uses original-pixel-center coordinates ((x+.5)*gainWidth/width-.5). Nearest-cell and bilinear log-gain approximations are reported separately. The latter approximates texture filtering; neither is an Android display screenshot or a measurement of the physical panel. Mean, RMS, maximum and nearest-rank p95/p99 absolute linear RGB/luminance errors use SDR white=1. Relative metrics provide both the targetY>=.05 subset and all samples with denominator max(targetY,.05). Signed luminance bias is recorded. These selected-sample distributions are observations, not exhaustive image error bounds or revised acceptance tolerances.

The baseline stress sets also encode a **test-only option C** through the unchanged PlatformUltraHdrEncoder; final C files come through the actual production ExportProcessor. This is a direct candidate encode, not an ExportProcessor eligibility decision. It uses the same sanitized sharpened target, a global maximum RGB channel P and knee K=.6. For P<=1 or per-pixel maximum m<=K, the base stays unchanged. Otherwise t=m-K, L=P-K, a=1-K, M=K+a*t/(a+t*(1-a/L)), factor=M/m. This curve is monotone, has slope1 at K, and maps the global peak to1. Base=target*factor. Scalar 4×4 luminance gain is recomputed against that base using the existing epsilon1/64 and gamma1. Like current A, gain measures the ideal float factor before half storage rounding. It removes global compression below the knee but can compress high SDR colors more than A in a scene whose HDR peak is highly saturated and has luminance<=1; it is not automatically a better look. The direct candidate file has no injected EXIF. The baseline did not change production. In the final source, C is shared by Social/Ultra HDR and explicit Ultra HDR requests retain every useful nonunit gain map; the existing .01-stop unity snap remains separate from the old1/3-stop policy.

Numerical reconstruction also splits sampled targets into interior and edge bins. An edge means a channel differs by more than .05 linear from any immediate four-connected neighbor. This absolute local-contrast definition is recorded alongside results; it is not a semantic segmentation. Greater variation between unchanged midtones and compressed highlights inside a 4×4 gain cell can increase scalar reconstruction error. The C formula and harness were independently reviewed before execution. Review corrected a .125 gain-texel interpolation offset and replaced a single gain-cell sample phase with balanced16-phase sampling, with explicit requests to assess this effect and colored peaks. Numerical validity alone does not approve C.


Enhanced captures also retain sampled nonnegative sharpened target RGB as gzip big-endian float32, per-sample edge flags, true means of all16 target pixels in each selected fixed4×4 evaluation cell and corresponding cell edge flags. Coordinates, cell origins and hashes are recorded in each sidecar. The phone cannot compress ALPHA_8 directly to PNG (failed final attempt retained). The adapter preserves original decoded raw gain bytes/config/stride and writes opaque grayscale ARGB PNG with each RGB byte equal to the original gain code. Every normalized PNG code must roundtrip exactly; numerical metrics continue reading the original decoded Gainmap pixels. Cell reconstruction computes all16 decoded pixels with the same bilinear gain estimator before averaging; it reports all/interior/edge selected-cell distributions, signed Y bias and the same fixed-denominator-floor tails.

The final Shinjuku stress pair additionally runs actual Social and Ultra HDR exports with a test-only maxTileSize1024 renderer override. The previous private override is restored in finally. Both formats start from identical forced-tile F16 renders; hashes and every decoded primary pixel's code differences against the corresponding single-render export are recorded, along with HDR and cell measurements. This is actual encoded-file evidence, distinct from a raw-frame clipping proxy.

A separate opt-in NaturalFormatBoundaryDeviceTest renders neutral astronaut/cloud crops at2160×3840 once, then explicitly applies a controlled linear exposure multiplier to that real GPU frame. It bisects to either side of the useful-gain identity floor and around the former1/3-stop cutoff, runs actual production Ultra HDR requests and explicit Social exports on the identical UHD frame, and retains JPEGs, decoded bases, formats, sampling and pre/encoded gain ratios. The below-floor fallback must be byte-identical to same-frame Social. All-pixel decoded code differences against same-frame Social isolate remaining chroma/codec effects. The former cutoff bracketing targets ±.01 measured gain stops, not ±.01 exposure EV. This tests format policy on natural pixels; it is not a GradeParams exposure test. Because ratioMax snaps headroom<=.01stop to unity, a nonunit .005-stop output is not representable by that API. Both sides of the former1/3-stop point should remain Ultra HDR under the new explicit request policy.
