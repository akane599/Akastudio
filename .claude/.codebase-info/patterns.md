# Patterns & Conventions
*Last Updated: 2026-10-21*

- **Frozen `api/` packages.** Each core module exposes its seams in one `api/` package (`core/ingestion/api`, `core/curator/api`, `core/color/api`, `core/composer/api`, `core/export/api`). Other modules and `:feature:studio` consume only these plus the factory functions; changing them is a cross-module change.
- **Pure Kotlin logic, thin Android adapters.** Algorithms (metrics, decision, colour math, encoders, Lanczos, crop, horizon, reducer) are plain Kotlin with no Android types; adapters (`MediaPickerIngestor`, `ml/MediaPipeAdapters`, `LiteRtNimaScorer`, `MediaStoreSink`, `PlatformEncoders`, `AndroidPreparerBackend`) wrap the platform behind small interfaces (`*Seams.kt`, `PreparerBackend`).
- **No DI framework.** Constructor injection; `StudioContainer` is the only composition root. Lazy construction keeps startup cheap.
- **JVM tests, no Robolectric.** Tests live in `<module>/src/test/kotlin` and run with `testDebugUnitTest`; Android-dependent code is tested through fakes of the seams. Studio ViewModel tests use `studioTestDispatchers(scheduler)` (distinct main/default/io test dispatchers on one scheduler), so `withContext` really switches dispatcher and cancellation paths can fail. The fakes have suspend/fail knobs. Shader tests run glslc as `310 es` plus `GlslEs300Check`, a source scan that rejects ES 3.10-only constructs. UI is covered by screenshot tests in `feature/studio/src/screenshotTest` and `app/src/screenshotTest` (`@PreviewTest @Preview`), refs under `screenshotTestDebug/reference`.
- **Device suites for device-only seams.** ContentResolver/MediaStore, EXIF on real files, GL/EGL, MediaPipe/LiteRT, platform codecs and Compose window/BACK are covered by `src/androidTest` suites run on the shared emulator under the flock lock (commands in onboarding.md). Test media goes under `Pictures/AkaStudioQA/` and is deleted after. The app flow suite drives the real `MainActivity`/`StudioViewModel` through `StudioIntent.ImportPhotos`, with no production test hooks.
- **MVI.** `StudioState` (immutable, kotlinx persistent collections) ← `StudioReducer.reduce(state, intent)` (pure); one-shot `StudioEffect`s live in `StudioViewModel`, and all side work of a story lives in its `StoryGeneration` (one child `SupervisorJob` scope per story; `launchWork(kind)` runs one work job at a time, joining and never cancelling its predecessor, and `cancelWork` either retires the generation or restores the last Ready story depending on the work kind). Work failures funnel through one handler keyed by work kind; failures of cancelled or retired work are only logged, never shown. Retiring a generation cancels its scope and defers the release of its photos until its work has joined.
- **Graceful degradation.** Model load failure → `CuratorModels.degraded` with heuristic fallbacks; weak GL → reduced/identity grader (`GraderSelection.kt`); Ultra HDR without headroom or below API 34 → Social JPEG.
- **NIMA single-thread confinement.** `ml/LiteRtNimaScorer.kt` compiles and runs the LiteRT model on one daemon executor thread named `nima-litert`; tests compare thread-name prefixes (coroutine debug appends a suffix).
- **CPU reference vs GPU parity.** `core/color/grade/CpuGradingPipeline` is the reference; `ShaderLayerGrader` must match within 2/255. `GradingParityFixtures` (JVM-tested by `GradingParityFixturesTest`) builds expected tables; `GradingParityProbe` is a device-only harness (needs GLES 3, logs under tag `GradingParity`).
- **Process-wide, never-closed heavies.** Renderer, models and container live for the process. The renderer is trimmed, never closed. The preparer recycles bitmaps only after `unregisterImage`, and GL register/unregister run under `NonCancellable`.
- **Photo ownership by coroutine context.** Candidate ids repeat across imports and `DefaultPhotoPreparer` is process-wide, so every `PhotoPreparer.prepare`/`release` call carries a `PhotoOwner` context element (`domain/PhotoOwner.kt`; one per `PreparedPhotoStore`, i.e. per story generation). Each `PhotoOwner` has a process-unique `id`, and the preparer registers a photo under the renderer key `<owner.id>/<candidateId>` (bare id for calls without an owner), returned as `ComposerPhoto.imageKey`; a release resolves the caller's keys only. Owners therefore never share a registration: a retired story's late registration or release cannot touch the replacement story's images, and two live view models sharing the container each hold their own. Failed unregisters stay tracked by key and are retried by whoever releases next. `PreparedPhotoStore.acquire` cleans up under `NonCancellable` and attaches a cleanup failure as `suppressed` to the primary failure or cancellation instead of replacing it.
- Decisions and numeric constants: `PROGRESS.md`.
