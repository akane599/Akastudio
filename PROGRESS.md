- 2026-10-21: the studio pipeline is one state machine per import batch: `StoryGeneration` owns a batch's ingestion session, candidates, prepared photos, jobs (one child scope of the view model's) and last Ready snapshot, moves the phase only through `StudioReducer` transition functions, and funnels every work failure through one handler keyed by the work's kind (first pipeline and restore retire, re-preparation restores, export returns to Ready); the view model only routes intents, holds the picker count and retires generations. Renderer registrations are owned: `PreparedPhotoStore` puts a `PhotoOwner` coroutine-context element on every preparer call and `DefaultPhotoPreparer` lets a release drop only the calling owner's registrations, so a retired story's late cleanup never unregisters what a newer story prepared under the same candidate id (also across two view models on one container). Candidate ids were not namespaced per session because that changes the frozen ingestion contract and its hash tests. A failed cleanup release is attached as suppressed to the preparation's own cancellation or failure, never replacing it. (audit AUD-01, AUD-02)
- 2026-10-21: the Ultra HDR base is tone-mapped so that no channel exceeds SDR white (the factor is the smaller of the luminance Reinhard factor and 1/max channel) and the gain map is computed from the sharpened frame that is actually encoded, so the decoded reconstruction matches the HDR source (red beside white: 56% → 4% error; boosted cyan: 5.5% → 0.3%). Consequence for SQ-66: saturated graded SDR colours that the old base clipped now count as headroom, so e.g. saturation +1 or temperature −1 on an SDR photo exports as Ultra HDR instead of falling back to the Social JPEG; the 1/3-stop rule and `ratioMax` parity are unchanged, and the "about 0.25 stop" overshoot note above describes the old luminance-only base. (audit AUD-03)
- 2026-10-21: `HalfFloatImage` export frames are premultiplied linear RGBA. Alpha-preserving outputs (PNG16, lossless WebP) store straight colour: the dither divides by alpha in linear light before the sRGB encode (zero alpha → zero colour) and the WebP bitmap is marked non-premultiplied. Opaque outputs (PNG8, Social JPEG, the Ultra HDR base) keep the premultiplied colour and drop alpha, i.e. composite over black; the preview matte is #0B0C0E (about 0.4% linear), so a fully transparent pixel is near-black in the preview and black in the file. Accepted: translucent export content is rare (transparent sources with the Frosted background) and the difference is below one 8-bit code at the dark end. `Lanczos3`/`LumaSharpen` still assume straight alpha; they only run on opaque paths. (audit AUD-08)
